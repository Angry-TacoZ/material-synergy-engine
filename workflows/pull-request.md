# Pull Request Workflow

1. Suggest an issue or PR when the change is meaningful enough to benefit from reviewable history; explain why.
2. For isolated substantial work, use a focused `codex/<short-change-name>` branch and stage files explicitly.
3. Confirm repository identity, remote, and target branch before pushing or opening a PR.
4. Run the canonical verifier and applicable security scans before opening the PR.
5. Open as a draft unless the user asks otherwise. Do not deploy from the PR branch without authorization.
6. Report the URL, branch, commit, checks, status, and remaining work.
